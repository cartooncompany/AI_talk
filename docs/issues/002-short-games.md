# 002. 게임이 너무 빨리 끝나는 문제

- **발생 단계**: 03 Mock 엔진 + Conductor
- **날짜**: 2026-08-20
- **상태**: 완화됨 (근본 해결은 아님)

## 증상

콘솔 데모로 게임을 돌리자 평균 6.1턴에 끝났다. 8개 시드 중 3개는 **1턴 만에**
종료됐다. 관전을 목적으로 하는 프로젝트인데 볼 것이 없는 길이였다.

```
seed=1    총 1턴    seed=7    총 1턴    seed=777  총 1턴
seed=42   총 4턴    seed=99   총 3턴    seed=123  총 9턴
```

## 조사

### 1차 추정 — 실수율이 높다 (부분적으로만 맞음)

`mistakeRate` 기본값 0.12가 높다고 보고 0.06으로 낮췄다. 1턴 종료는 사라졌으나
평균은 6.1턴에 머물렀다. 실수율을 0.015까지 낮춰도 평균 8.1턴이었다.
실수율만으로 설명되지 않는 요인이 있었다.

### 결정적 단서 — 실수율 0에서도 게임이 끝난다

`mistakeRate: 0`으로 300게임을 돌렸다. 실수를 전혀 하지 않도록 했는데도
**292회가 규칙 위반으로 종료**됐다. 로직 결함을 의심할 상황이었다.

원인은 `mock.ts`의 막다른 길 처리였다. 후보가 0개면 `mistakeRate`와 무관하게
헛소리를 반환하도록 되어 있었고, 그것이 "시작 글자 틀림"으로 판정됐다.

초기 집계에서 이 경로가 보이지 않은 이유는, 실수로 낸 헛소리와 막다른 길에서
낸 헛소리가 **같은 사유 문구**("시작 글자 틀림")로 판정되어 구분되지 않았기
때문이다. 사유 문구가 아니라 그 시점의 후보 수를 직접 계산해 재집계했다.

### 실제 원인 — 사전 고갈

| 실수율 | 평균 턴 | 막다른 길 | 실수 |
|---|---|---|---|
| 0 | 7.5 | 296회 (99%) | 0 |
| 0.06 | 5.3 | 198회 (66%) | 102회 |

**막다른 길이 지배적 원인**이었다. 사전이 432개로 작아 몇 턴만 지나면
이어갈 단어가 고갈된다. 2단계에서 막다른 단어 비율을 15%로 낮췄지만,
게임이 진행되며 단어가 소진되면 남은 후보가 전부 막다른 길이 되는 상황이
자주 발생한다.

## 해결

Mock 엔진이 후보를 고를 때 **상대가 이어받을 수 있는 단어를 우선**하도록 했다
(`survivingCandidates`). 실제로 끝말잇기를 두는 사람도 이렇게 하므로
자연스럽고, 규칙을 바꾸지 않으면서 게임을 늘린다.

모든 후보가 막다른 길이면 폴백으로 원래 후보를 그대로 쓴다 — 이어갈 수는
있어야 하기 때문이다.

여기에 더해 기본 실수율을 0.12 → 0.04로 조정했다.

### 결과

| | 개선 전 | 개선 후 |
|---|---|---|
| 평균 턴 (실수율 0) | 7.5 | **15.4** |
| 평균 턴 (기본 설정) | 6.1 | **10.6** |
| 10턴 이상 (300게임) | 87 | **139** |
| 3턴 이하 | 105 | **55** |

## 부수적으로 고친 것

mulberry32는 시드 직후 첫 출력이 시드값에 강하게 좌우된다. 인접한 시드끼리
초반 난수가 비슷해 게임이 같은 방식으로 시작되는 일이 잦았다. 상태를 8회
미리 돌려 흩뜨리는 워밍업을 추가했다.

## 남은 것

**근본 해결은 사전을 늘리는 것이다.** 432개는 끝말잇기를 오래 이어가기에
부족하다. 다만 이번 단계 범위를 넘어서므로 완화에서 멈췄다.

실제 AI를 연동하는 단계에서는 사전 자체가 사라지거나(AI가 아는 단어를 씀)
사전 API로 대체되므로, 이 문제는 자연히 해소될 가능성이 높다. 그때까지는
현재 설정으로 충분하다.

관련 조정 지점:
- `createMockEngine({ mistakeRate })` — 기본 0.04
- `createWordChain({ maxTurns })` — 기본 50
