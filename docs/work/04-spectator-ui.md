# 04. 관전 UI

- **날짜**: 2026-08-20
- **이슈**: [#8](https://github.com/cartooncompany/AI_talk/issues/8)
- **상태**: 완료

## 목표

Conductor를 화면에 붙인다. 사용자는 개입 없이 관전만 한다.

## 한 일

### 1. 코어와 UI의 경계 (`src/ui/hooks/useMatch.ts`)

Conductor 이벤트를 React 상태로 옮기는 유일한 지점. 컴포넌트에는 렌더링에
필요한 것만 노출한다.

`scenario`·`engines`가 바뀌면 새 게임이므로 Conductor를 다시 만들지만,
**속도(`turnDelay`)는 의존성에 넣지 않는다.** 속도는 게임의 정체성이 아니라
재생 설정이기 때문이다. 자세한 경위는 [이슈 003](../issues/003-speed-change-resets-game.md).

### 2. 관전 연출

계획안에서 "결과가 한 번에 툭 나오면 관전할 게 없다"고 짚은 부분이다.

| 훅 | 역할 |
|---|---|
| `useTypewriter` | 글자가 하나씩 나타난다. 마지막 발화만 애니메이션 |
| `useAutoScroll` | 새 메시지를 따라간다. 사용자가 위로 올리면 멈춘다 |

`useAutoScroll`에서 주의한 점: smooth 스크롤은 여러 프레임에 걸쳐 진행되고
그동안 scroll 이벤트가 계속 발생한다. 그 중간값으로 "바닥에 있는지"를
판정하면 아직 도착하지 않았다는 이유로 자동 추적이 꺼진다. 우리가 건
스크롤이 멎을 때까지는 사용자 입력으로 오인하지 않도록 했다.

승패 카드는 마지막 턴 *이후에* 붙으므로, 의존성을 `turns.length`가 아니라
턴·생각중·결과를 합친 키로 두었다. 이걸 놓쳐 처음엔 승패 카드가 화면
밖에 머물렀다.

접근성: `prefers-reduced-motion`이 켜져 있으면 타이핑 없이 즉시 표시한다.

### 3. 컴포넌트

```
SpectatorView          상단 헤더 · 중앙 스트림 · 하단 컨트롤
├─ Scoreboard          대전 카드. 현재 차례와 승패 표시
├─ Bubble              발화 하나. 좌/우 정렬, 무효는 붉게
├─ Thinking            생각 중 점 세 개
└─ Controls            시작·일시정지·재개·리셋·속도
```

`src/ui/match-setup.ts`에 에이전트와 엔진 구성을 모아뒀다. 실제 API를
연동할 때 이 파일의 `engines`만 바꾸면 된다.

### 4. 스타일 (`src/index.css`)

라이트를 기본으로 정의하고 다크는 `prefers-color-scheme`으로 덮어쓴다.
색은 전부 토큰이라 테마 전환 시 한 곳만 바뀐다.

말풍선은 `align-self: flex-start`로 내용 폭에 맞춘다. 이게 없으면 무효 사유
텍스트가 길 때 풍선이 화면 폭 전체로 늘어난다.

## 발생한 이슈

- [003. 진행 중 속도를 바꾸면 게임이 리셋되는 문제](../issues/003-speed-change-resets-game.md) — 해결됨

  `turnDelay`가 Conductor 의존성에 있어 속도를 바꿀 때마다 게임이 처음으로
  돌아갔다. 관전자의 자연스러운 행동에서 나오는 버그라 치명적이었다.
  Conductor가 매 턴 현재 값을 읽도록 바꾸고 회귀 테스트를 추가했다.

- [004. jsdom이 Node 23에서 ESM 충돌로 동작하지 않는 문제](../issues/004-jsdom-esm-conflict.md) — 해결됨

  jsdom 도입으로 기존 65개 테스트가 전부 깨졌다. 테스트 환경을 파일별로
  좁히고 happy-dom으로 교체했다.
