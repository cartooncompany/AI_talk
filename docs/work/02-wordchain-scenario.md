# 02. 끝말잇기 규칙 엔진

- **날짜**: 2026-08-20
- **이슈**: [#3](https://github.com/cartooncompany/AI_talk/issues/3)
- **상태**: 완료

## 목표

`Scenario` 인터페이스를 구현한 끝말잇기 규칙 엔진. UI 없이 테스트로 검증 가능해야 한다.

## 한 일

### 1. 한글 음절 유틸 (`src/core/hangul.ts`)

유니코드 한글 음절 영역은 `0xAC00 + 초성*588 + 중성*28 + 종성` 규칙으로
구성되므로 산술로 분해·조합했다. 외부 라이브러리를 쓰지 않은 이유는 필요한
연산이 이 정도로 단순하고, 의존성 없이 서버로 옮길 수 있어야 하기 때문이다.

- `isHangulSyllable` / `isHangulWord` — 완성형 음절 검사. 자모 단독(`ㄱ`)은 거부한다.
- `decompose` / `compose` — 초·중·종성 분해와 조합
- `firstChar` / `lastChar`

### 2. 두음법칙 (`src/core/dueum.ts`)

끝말잇기에서 판정이 가장 많이 갈리는 부분이라 별도 모듈로 분리했다.

| 조건 | 변환 | 예 |
|---|---|---|
| ㄹ + ㅑㅕㅛㅠㅣㅐㅖ | → ㅇ | 려 → 여, 례 → 예 |
| ㄹ + 그 외 모음 | → ㄴ | 락 → 낙 |
| ㄴ + ㅑㅕㅛㅠㅣ | → ㅇ | 녀 → 여 |

`allowedStarts(char)`가 "이 글자를 이어받을 때 쓸 수 있는 시작 글자들"을 반환한다.
ㄹ→ㄴ→ㅇ 연쇄도 따라가되, `락 → 낙`이 `악`까지 가지 않도록 조건을 분리했다.

검증 결과: `례 → 예`(중간에 `녜`를 거치지 않음), `락 → 낙`(과잉 변환 없음) 모두 의도대로 동작.

### 3. 단어 사전 (`src/data/words.ts`)

432개 한국어 명사. 로직 없이 데이터만 둔다 — 실제 AI 연동 단계에서
사전 API나 AI 심판으로 대체될 수 있기 때문이다.

사전 감사를 스크립트로 돌려 품질을 확인했다.

| 항목 | 결과 |
|---|---|
| 총 단어 수 | 432 |
| 중복 | 없음 |
| 비한글·한 글자 | 없음 |
| 막다른 단어 | 65개 (15.0%) |

초기 사전은 막다른 단어가 24%로 많아 게임이 조기 종료됐다. 빈도가 높은
끝 글자(개·래·을·름·늘·락·스·위)를 받는 단어를 보강해 15%로 낮췄다.
보강 과정에서 실제 명사가 아닌 조어(`름값`, `켓시`, `섯가락` 등 9개)가
섞여 들어가 제거했다 — 사전이 판정의 근거이므로 신뢰성이 중요하다.

15%는 그대로 뒀다. 실제 끝말잇기에도 막다른 단어는 존재하고, 게임이
끝날 수 있어야 승패 판정을 검증할 수 있다.

### 4. Scenario 구현 (`src/core/scenarios/wordchain.ts`)

`createWordChain(options)` 팩토리로 만든다. 옵션은 두음법칙 허용 여부,
최대 턴 수, 시작 단어.

판정 순서 — 구체적인 사유를 먼저 돌려주기 위해 이 순서를 지킨다.

```
빈 문자열 → 한글 여부 → 길이 → 중복 → 시작 글자 → 사전 등재
```

상태를 갖지 않는다. 판정에 필요한 정보는 전부 `history`로 받으므로
순수 함수이고, 같은 입력에 항상 같은 결과가 나온다.

`instructionFor`는 Engine에 전달할 지시문을 만든다. 두음법칙이 적용되면
대안 글자를 함께 알려주고, 이미 나온 단어 목록도 포함한다. 실제 AI를
붙였을 때 이 문장이 그대로 프롬프트가 된다.

```

```

```
npm test   → 42 passed
npm run lint  → 통과
npm run build → 통과 (테스트 코드는 번들에 미포함 확인)
```

테스트 작성 중 `리본`이 사전에서 제거됐다고 잘못 단정한 케이스가 하나
있었다. 실제로 제거한 건 `본보기`였고, `리본`이 통과하는 것이 올바른
동작이라 테스트 쪽을 수정했다.
